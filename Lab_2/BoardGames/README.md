# Лабораторная работа №2: Базы данных и ORM (BoardGames API)

## 📌 Описание проекта
Данный проект представляет собой RESTful API для управления каталогом настольных игр. Основная цель второй лабораторной работы — проектирование и реализация надежного слоя работы с данными (Data Access Layer) с использованием современных подходов контейнеризации и ORM.

Проект построен по архитектурному паттерну **MVC / Repository-Service-Controller**, что обеспечивает строгое разделение бизнес-логики и логики работы с базой данных.

## 🛠 Технологический стек
* **Язык программирования:** Python 3.12+
* **Фреймворк:** FastAPI
* **База данных:** PostgreSQL
* **ORM:** SQLAlchemy 2.0 (Core & ORM)
* **Миграции:** Alembic
* **Контейнеризация:** Docker & Docker Compose

## 🚀 Ключевые реализованные функции (Требования Лаб. №2)
1. **Объектно-реляционное отображение (ORM):** Реализованы декларативные модели данных (классы Python) для таблиц `users` и `boardgames`.
2. **Паттерн Репозиторий:** Все SQL-запросы изолированы в классах репозиториев (`app/repository/`). Код API не работает с базой данных напрямую.
3. **Пагинация (Pagination):** Реализована порционная выдача списка игр с использованием параметров `limit` и `offset` для снижения нагрузки на БД.
4. **Мягкое удаление (Soft Delete):** Безопасное удаление записей. Вместо физического удаления (`DELETE`) используется колонка `deleted_at`. Методы чтения (`GET`) автоматически отфильтровывают удаленные записи (`deleted_at IS NULL`).
5. **Автоматическое развертывание среды:** База данных и само приложение автоматически поднимаются и связываются друг с другом в единой Docker-сети.

## 🐳 Инструкция по запуску

Проект полностью упакован в Docker-контейнеры. Для запуска не требуется локальная установка Python или PostgreSQL.

1. Убедитесь, что у вас запущен **Docker Desktop** (или демон Docker).
2. Склонируйте репозиторий и перейдите в корневую папку проекта.
3. Выполните команду для сборки и запуска контейнеров:

```bash
docker-compose up --build
4. Дождитесь появления в консоли сообщения об успешном старте приложения и базы данных.

Примечание: При первом запуске база данных будет пустой, но система автоматически создаст все необходимые таблицы согласно моделям SQLAlchemy.

🧪 Тестирование и документация
После запуска контейнеров интерактивная документация (Swagger UI) будет доступна по адресу:
👉 http://localhost:4200/docs

Там можно протестировать выполнение всех CRUD-операций (Создание, Чтение, Обновление, Удаление) без использования сторонних утилит вроде Postman.

🗄️ Работа с базой данных "под капотом"
При необходимости проверить физическое состояние базы данных (например, убедиться в работоспособности Soft Delete), можно подключиться к контейнеру с PostgreSQL:

Откройте новый терминал.

Войдите в контейнер базы данных:

docker exec -it boardgames_postgres psql -U postgres -d postgres

Переключитесь на базу данных проекта:

\c boardgames_db

Выполните SQL-запрос для просмотра всех записей, включая удаленные:

SELECT id, title, deleted_at FROM boardgames;
